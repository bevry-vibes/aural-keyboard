## Context

Platform parity per the DESIGN §8 sequencing ruling: the Linux port changes no
behavior; existing defaults carry over as-is. Target environment: Fedora 44,
GNOME Shell 50.4, Wayland (GNOME 49+ has no X11 fallback, so the original X11
route from DESIGN §6 was dead on arrival — see the prior-art survey plan
`1788551509000-linux-prior-art-survey.md`).

## Work

- **Hook** (`src/hook/linux.rs`) — listen-only evdev readers over
  `/dev/input/event*`, one per keyboard-class device (a device is a keyboard when
  it can produce both `KEY_A` and `KEY_SPACE` — excludes power buttons/headphone
  jacks), one `poll(2)` loop on a dedicated thread. Devices never grabbed
  (pass-through parity with the LL hook / listen-only tap). Hotplug: device set
  rescanned every 5 s (poll timeout 250 ms bounds shutdown latency). `Btn_*`/misc
  codes (0x100+) filtered before translation so mouse clicks stay silent;
  unmapped keyboard codes fall to `VK_UNKNOWN` (default drum).
- **Why evdev** — evdev sits below the display server and works identically under
  X11 and Wayland. Price: reading `/dev/input/event*` requires the `input` group
  (`sudo usermod -aG input $USER` + re-login); `aural doctor` and `spawn` report
  it. Unlike Win/mac hooks, evdev sees the lock screen — documented behavior
  difference.
- **Key identity** — `src/keycodes.rs` gained an evdev `KEY_*` → VK table
  (set-1 scancodes positional; letters US-assumed like macOS; layout-true
  characters stay deferred). Unit-tested table (uniqueness, spot checks, hotkey
  reverse lookup).
- **Mute hotkey** — detected in the poll loop from the shared pressed-table
  (evdev reports modifier presses directly, like macOS `flagsChanged`); same
  packed `(mods << 32) | vk` config. Default unchanged: Ctrl+Shift+F12.
- **Daemon** — `daemon/unix.rs` shared POSIX code (setsid detach, PID file,
  flock single-instance, log redirection); autostart leg: XDG autostart
  (`~/.config/autostart/com.bevry.aural.desktop`), parity with the Windows Run
  key / macOS LaunchAgent.
- **Tray** — `menubar.rs` refactored into shared menu logic + per-platform
  shells. Linux: `tray-icon` with its `gtk` feature (muda/gtk +
  libappindicator; `libxdo` disabled), `gtk::init()` + `gtk::main()` on the main
  thread, menu events polled from muda's `MenuEvent::receiver()` crossbeam
  channel via a 50 ms glib timeout. GNOME shows the tray only with the
  **AppIndicator and KStatusNotifierItem Support** extension; `aural doctor`
  reports when missing. Engine on a worker thread as on macOS; flock
  single-instance excludes `start` vs `menubar` mutually.
- **Audio** — cpal 0.18 ALSA backend, engine code unchanged; build dep
  `alsa-lib-devel`.
- **CI/release** — `linux` job (ubuntu-22.04: `libappindicator3-dev` still
  packaged there; `libasound2-dev`, `libgtk-3-dev`), same fmt/clippy/test/build
  gates; artifact `aural-linux-x64.tar.gz` + sha256.
