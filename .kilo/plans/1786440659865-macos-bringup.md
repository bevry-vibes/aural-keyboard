## Blocker 1: Secure Event Input — RESOLVED (this session)

- Symptom: tap delivered zero keyDown/keyUp; only `flagsChanged`
  (modifiers/Caps Lock) leaked → "Caps Lock sounds, letters don't".
- Root cause (IORegistry): `kCGSSessionSecureInputPID = 944` = **Terminal.app**
  (launchd, at boot) with `SecureKeyboardEntry = true`. macOS 26 withholds
  keyDown/keyUp from ALL event taps while any app holds secure input.
- Ghostty (host terminal) **exonerated** — its toggle had no effect because it
  never held the flag (Ghostty can re-hold later via `macos-auto-secure-input`
  on password prompts; ghostty#11883).
- Fix: user unchecked Terminal.app Shell → Secure Keyboard Entry. Verified:
  `IsSecureEventInputEnabled = False`, `kCGSSessionSecureInputPID` gone.
- Not a freak thing (documented: thock#127, ghostty#11883) — so per user
  decision we codify detection (doctor) and a workaround; restart does NOT
  clear the flag (disproves §10 assumption).

## Blocker 2 (goal): `aural run` must name `aural/Aural` in the TCC prompt

Research (this session) found the correct mechanism:

- The API is **`responsibility_spawnattrs_setdisclaim(posix_spawnattr_t *) → int`**
  — DESIGN and earlier probes tested the wrong name (`setdisown`, removed).
  `setdisclaim` is **present in libSystem on macOS 26** (verified via dlsym).
  It is the documented private mechanism Terminal.app/iTerm2 use; macOS 26
  still honors it (orca#12971; Qt "Curious Case" blog; Chromium/LLDB/Firefox;
  `disclaim` crate; `selfauth`).
- DESIGN learning #1 (responsible=com.mitchellh.ghostty from real tccd log) is
  authoritative: **Ghostty does not disclaim** (contradicting selfauth's README;
  orca notes only Terminal.app/iTerm2 set it). So aural must disclaim itself.
- With disclaim, the responsible process becomes aural itself → TCC prompt and
  grant key to aural's code requirement (ad-hoc cdhash, or the stable
  `aural-dev` self-signed cert). This also simplifies the README permission
  table (all launch modes → aural).

## Tasks (in order)

1. **Live-verify tap works now** (user types; `AURAL_LOG=1` build instruments):
   `launchctl setenv AURAL_LOG 1`; run

   user types; `kill -INT <pid>`; read files for `tap event type 10/11` +

2. **Self-disclaim re-exec** (new, macOS-only) so plain `aural run`/`bench`/
   `start` name aural. Put it in a new `src/macos.rs` (main-level concern; not
   `hook/macos.rs`, which owns only the tap). **IMPLEMENTED as built:**
   - FFI: `libc::dlsym` on `responsibility_spawnattrs_setdisclaim` from
     libSystem. The signature is **two-arg** — `(posix_spawnattr_t *,
     int disclaim) -> int` (Apple `spawn_private.h`). A one-arg call leaves
     `disclaim` as caller garbage and **silently does not set the flag**
     (caught this live via tccd). Check the return and bail if non-zero.
     `posix_spawnattr_t` is an opaque `*mut c_void` handle (init to null,
     then `posix_spawnattr_init`). No static link (symbol absent from SDK).
   - Re-exec target: `std::env::current_exe()` (NOT `argv[0]`), preserving
     `args_os()` and the full env + `AURAL_DISCLAIMED=1`. No file actions —
     inherit stdin/stdout/stderr (`--stdin`, live `bench` typing, Ctrl+C).
   - **child-spawn is the primary** (implemented, verified): Terminal.app/
     iTerm2/selfauth/disclaim all spawn without `POSIX_SPAWN_SETEXEC` because
     the disclaim flag is applied in the spawn child and `SETEXEC` bypasses
     it. The parent forwards SIGINT/SIGTERM/SIGHUP and exits with the child's
     status, preserving foreground Ctrl+C and exit codes. (Setexec path left
     as an untried alternative; do not flip without re-verifying.)
   - **Guard-leak fix:** `spawn_detached` `.env_remove("AURAL_DISCLAIMED")` so
     the daemon child re-evaluates disclaim for itself.
   - **Disclaim set = `run` (non-stdin), live `bench`, and `doctor`** — the
     hook-creating commands plus the reporting one, so `aural doctor` reflects
     aural's own grant. `--stdin`, `--synthetic`, and the control commands
     (`start`/`stop`/`status`/`mute`/`volume`/`about`/`install`/`uninstall`)
     never re-exec.
   - **Verified (no sudo):** child's responsible pid equals itself via the
     private `responsibility_get_pid_responsible_for_pid(pid)`; tccd
     `AUTHREQ_ATTRIBUTION` shows no inherited `responsible=` for the child
     (only `accessing=…aural`); the real TCC prompt named **"aural"**.
